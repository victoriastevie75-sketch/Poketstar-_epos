Critical Issues Identified

When running native Windows .EXE binaries or batch launchers on customer PCs, startup failures typically stem from four root causes:

Issue 1: Missing Server Route Dependencies
Location: server.js lines 66–74
Problem: Hardcoded requires for missing modules (./server/routes/auth.routes, payments.routes, products.routes, sales.routes) cause Node.js to crash immediately on initialization.
Impact: The HTTP server halts before opening port 3000, leading to browser connection refused errors.
Issue 2: Module Packaging Boundaries & Bundled Dependencies
Problem: Standalone executables need fallback routes and embedded static asset paths if external node_modules/ directories are omitted or corrupted in transfer.
Issue 3: Browser Path Auto-Detection in Desktop Launcher
Location: desktop-launcher.js lines 69–87
Problem: Windows systems without Google Chrome in default folders failed to launch kiosk mode. Needs multi-browser discovery (Edge, Chrome, Brave, Rundll32 Shell fallback).
Issue 4: Port 3000 Binding Conflicts (EADDRINUSE)
Problem: If port 3000 is occupied by another service or previously unclosed POS instance, the server must automatically cycle to the next available port (3001, 3002...) and launch the browser with the matching URL.

Bulletproof Solutions & Implemented Code

Solution 1: Create Complete Server Route Files
Implemented

Create server/routes/ with clean modular handlers for auth, payments, products, and sales:

server/routes/products.routes.js 
const express = require('express');
const fs = require('fs');
const path = require('path');
const router = express.Router();

router.get('/', (req, res) => {
  try {
    const productsPath = path.join(__dirname, '../../products.json');
    if (fs.existsSync(productsPath)) {
      const products = JSON.parse(fs.readFileSync(productsPath, 'utf8'));
      return res.json(products);
    }
    res.json([]);
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
});

module.exports = router;
Solution 2: Resilient Route Mounting in server.js
Implemented

Wrap all route registrations with guarded try/catch blocks so the server never crashes even if optional routes are missing:

server.js (Safe Route Mounting) 
try {
  const authRoutes = require('./server/routes/auth.routes');
  app.use('/api/auth', authRoutes);
} catch (e) {
  console.warn('[POS] Auth routes skipped:', e.message);
}

try {
  const paymentsRoutes = require('./server/routes/payments.routes');
  app.use('/api/payments', paymentsRoutes);
} catch (e) {
  console.warn('[POS] Payments routes skipped:', e.message);
}
Solution 3: Multi-Browser Kiosk Launcher & Auto-Detect
Implemented

Detects Edge, Chrome, and Brave across both Program Files and LocalAppData, launching with --app="http://localhost:3000" for a clean desktop window:

desktop-launcher.js (Auto Browser Detection) 
// Auto-scan browser executable paths in Windows
const browserExecutables = [
  path.join(progFilesX86, 'Microsoft/Edge/Application/msedge.exe'),
  path.join(progFiles, 'Microsoft/Edge/Application/msedge.exe'),
  path.join(progFiles, 'Google/Chrome/Application/chrome.exe'),
  path.join(progFilesX86, 'Google/Chrome/Application/chrome.exe')
].filter(Boolean);

// Fallback to cmd /c start "" "http://localhost:3000" if no dedicated path exists
